# Architecture

The official authenticator resolves the local key, exchanges it for a bearer token and manages its own token cache. The endpoint registry maps a category to a documented method. The exporter iterates every day or bounded window and stores each original response structure, plus paginated activity results and downloaded activity ZIP bytes. Each completed query is checkpointed after atomic file replacement with its SHA-256; a restart verifies the hash before skipping it. Failures are recorded independently and can be retried on the next run. Rate-limit and selected network/server errors receive bounded retry and jitter. Report generation is offline and recursively counts observed field types without including field values.

Known limitations: current code holds one token for the session and does not refresh on expiry or 401; no explicit timeout configuration is passed to the official client; Retry-After HTTP-date values are not parsed; the checkpoint plan is not a complete pending-work ledger; activity page stop conditions require live verification. Report counts are counts of query results and schema occurrences, not authoritative record or day counts. This is an experimental implementation.
